Feasibility & Rebuild Blueprint

ถอดโครง SamuraiVdo 1.12 ออกมาทีละชิ้น แล้วแมปว่าเราต้องสร้างอะไรใหม่บ้าง — พร้อมประเมินความยากจริงและลำดับการลงมือ

เป็นไปได้ 100%

ไม่มีชิ้นส่วนไหนใช้เทคโนโลยีลับหรือพิเศษ — ทุกอย่างเป็นของมาตรฐานที่สร้างใหม่ได้หมด (accessibility automation, ตัดต่อ Media3, AI แคปชั่น, REST backend, เว็บคุมบอท). สิ่งที่ต้องยอมรับคือมันเป็นโปรเจกต์จริงจัง 3 ก้อน ไม่ใช่แอปเดียว และมี “จุดยากที่ต้องดูแลต่อเนื่อง” อยู่หนึ่งจุด ซึ่งอธิบายไว้ด้านล่าง

Architecture

ระบบเต็มมี 3 ก้อน

ต้นฉบับเป็น client–server ถ้าจะ “เหมือนทุกอย่าง” ต้องสร้างครบทั้งสามส่วน

01 · ANDROID APP

แอปบนมือถือ

มือกดจอ + เครื่องยนต์เจนคลิป: accessibility service, foreground service, ตัดต่อวิดีโอ, AI แคปชั่น, ปุ่มลอย

02 · BACKEND

เซิร์ฟเวอร์ของเรา

REST API เก็บชุดสินค้า (dataset), รับ-ส่งคำสั่ง, สถานะเครื่อง, heartbeat, คีย์ AI — แทนที่เซิร์ฟเวอร์เดิมที่เราไม่มี

03 · WEB DASHBOARD

เว็บคุมบอท

หน้าเว็บสั่ง start/stop/pause, ตั้งค่า, ดูสถานะเครื่องแบบเรียลไทม์ — ตรงกับที่ต้นฉบับเรียก “คำสั่งจากเว็บ”

The one hard part

จุดที่ยากจริง — และยากตลอดไป

Accessibility automation ของ Shopee/TikTok คือหัวใจ และเป็นจุดเปราะที่สุด เพราะมันพึ่งพา “หน้าตา UI” ของแอปปลายทางที่เราไม่ได้เป็นเจ้าของ ต้นฉบับ hardcode ตำแหน่งปุ่ม/ไอดีของ Shopee ไว้

  • ต้องไล่ส่อง UI ของ Shopee เอง (view-id, ข้อความปุ่ม, ลำดับหน้าจอ) เพื่อสร้าง selector ของเรา — ทำได้ แต่กินเวลา
  • เมื่อ Shopee/TikTok อัปเดตแอป ปุ่มขยับ → บอทพัง ต้องตามแก้ selector เรื่อยๆ นี่คือ “ค่าบำรุงรักษา” ที่ต้องมีคนดูแล
  • ส่วนอื่น (ตัดต่อ, AI, backend, เว็บ) สร้างเสร็จแล้วนิ่ง แต่ส่วนนี้ต้องดูแลต่อเนื่อง
Roadmap

ลำดับการสร้าง (แนะนำ)

สร้างให้เห็นผลเร็วก่อน แล้วค่อยต่อระบบรีโมท — แต่ละเฟสได้ของที่ใช้งานได้จริง

1
Standalone core

แอปเดี่ยว: เลือกสินค้า → ตัดต่อ → AI แคปชั่น

ไม่มี server ไม่มี login คุมบนมือถือ ได้ไฟล์คลิปพร้อมแคปชั่นออกมา พิสูจน์ว่าเครื่องยนต์ทำงาน

2
Auto-post

ต่อ Accessibility automation โพสต์เข้า Shopee

จุดยากที่สุด ทำทีละแพลตฟอร์ม เริ่มจาก Shopee ก่อน + ปุ่มลอย + ระบบดึงแอปกลับ

3
Backend + remote

เซิร์ฟเวอร์ + คิวคำสั่ง + สถานะ

ให้คุมหลายเครื่องจากส่วนกลาง: dataset store, command queue, heartbeat, device-id auto-register (แทน login)

4
Web dashboard

หน้าเว็บคุมบอท + มอนิเตอร์

สั่งงาน ตั้งค่า และดูสถานะทุกเครื่องแบบเรียลไทม์ — ครบเหมือนต้นฉบับ
